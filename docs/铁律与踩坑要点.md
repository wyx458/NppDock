# 铁律与踩坑要点 — NppDock

这份文件是 `踩坑记录.md`（约 2800 行的逐轮迭代流水账）的**结论提炼**：只留"会再咬人的规矩"，
扔掉"哪一轮怎么改的"过程。给**没有上下文的后来人 / AI agent**看——动手改代码前，先扫一遍
对应主题的那几条。每条三行：结论（**规矩**/**坑**）、违反后的**症状**、可执行的**做法**。
括号里的 `（历史：踩坑记录 第 N 节）` 是出处；那份原文已从仓库删除（早期过程文档都不随仓库分发）。

## 一、窗口与重绘

- **坑**：嵌入窗口的祖先被宿主改了尺寸后，它不再进入"待重画"名单，界面一片白，松手也不自愈。
  - **为什么**：窗口层级、可见性、控件矩形全对、进程也活着，屏幕上却只剩底色；`SetWindowPos`（哪怕尺寸真变了）、空 `SetWindowPos`、`SW_HIDE+SW_SHOW` 全都无效。
  - **怎么做**：改完尺寸显式 `RedrawWindow(h,nullptr,nullptr,RDW_INVALIDATE|RDW_ERASE|RDW_ALLCHILDREN)`——`RDW_ALLCHILDREN` 不能少，否则应用自己的子控件仍不画。（历史：踩坑记录 第9.1节）
- **规矩**：只"作废"不够——作废要排到本轮消息队列尾部，并用 120ms 防抖在尺寸停住后补最后一次。
  - **为什么**：宿主一次鼠标移动的顺序是"改父窗口尺寸→改我们尺寸→布局→作废"，最后那步作废会被前一步引发的子窗口可见区域重算冲掉；拖动中宿主还临时压制了整棵树的重绘，压制期间任何 `RedrawWindow` 都是白做。
  - **怎么做**：用 `PostMessage` 私有消息把作废排到队列尾（用 `_repaintPosted` 拦着，队列里最多一条），再 `SetTimer` 一次性 120ms 防抖；三层缺一症状都会回来。（历史：踩坑记录 第9.2、9.3、9.5节）
- **规矩**：本方（N++ UI 线程）永远不要对跨进程子窗口做同步重画，绝不加 `RDW_UPDATENOW`。
  - **为什么**：目标窗口在另一个进程，"立刻画完"会让双方互等，直接把整个 Notepad++ 卡死（任务栏"未响应"、只剩底色），从外面再 `RedrawWindow` 也救不回。
  - **怎么做**：跨进程重画只投异步 `RedrawWindow(RDW_INVALIDATE|RDW_ERASE|RDW_ALLCHILDREN)`；需要"确保画出来"就靠时机（防抖定时器），不靠"强制"。（历史：踩坑记录 第9.6节）
- **规矩**：卡死时先看 `IsHungAppWindow(宿主)==1` 且应用 `SendMessageTimeout(...WM_NULL)` 秒回——这个组合几乎可定案"卡住的是我们"。
  - **为什么**：它等于"只有宿主无响应、应用自己活着"，说明是本方在等对面。
  - **怎么做**：命中就先查自己这边有没有同步跨进程调用。（历史：踩坑记录 第9.6节）
- **规矩**：跨窗口的钩子要挂在"状态真正发生变化的那一层窗口"上。
  - **为什么**：隐藏→唤出时尺寸没变，改尺寸那套补偿救不了它（应用整块空白）；而外部（探针、菜单命令、框架恢复面板）能绕过 `TogglePanel` 直接发 `NPPM_DMMSHOW`，挂在 `onShow()` 上的钩子根本不会被调用。
  - **怎么做**：本例钩子挂**容器**的 `WM_SHOWWINDOW`；判断方法就是问"是哪个窗口的 `WS_VISIBLE`/尺寸真的变了"。（历史：踩坑记录 第9.7、18.4节）

## 二、跨进程通信

- **规矩**：跨进程只发"参数里没有指针"的消息。
  - **为什么**：`SendMessage` 跨进程不封送指针，对面会按我们的地址去写——探针 `TCM_GETITEMRECT` 把 N++ 写崩、应用发 `NPPM_DOOPEN`（lParam 是指针）也把 N++ 写崩、未保存内容一起丢。
  - **怎么做**：要位置就自己推算或换真正处理指针的 API（`GetWindowRect`/`GetMenuItemRect`）；要传数据用 `WM_COPYDATA`；要对方做事就 `CreateProcess` 走命令行（N++ 单实例会转交）。（历史：踩坑记录 第8.5、19.1、21.6节）
- **规矩**：在 UI 线程上等另一个进程退出时，必须边等边泵消息。
  - **为什么**：销毁"父窗口在别的进程"的子窗口时，系统要向父窗口同步发 `WM_PARENTNOTIFY`；父窗口的 UI 线程正卡在 `WaitForSingleObject` 上 → 双方互等，关闭僵 3 秒。
  - **怎么做**：改用 `MsgWaitForMultipleObjects(1,&hProc,FALSE,timeout,QS_ALLINPUT)`，返回"有消息"时 `PeekMessage+Dispatch` 一轮（实测 3.0s→0.345s）。（历史：踩坑记录 第8.6节）
- **规矩**：把应用进程放进同一个 Job Object，并设 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。
  - **为什么**：宿主被强杀/崩溃时插件没机会执行任何代码，正常退出路径下应用会变成孤儿进程。
  - **怎么做**：作业句柄随宿主销毁，由内核负责杀掉作业内所有进程——这是唯一不依赖"插件代码被执行"的回收方式。（历史：踩坑记录 第8.7节）
- **规矩**：应用与宿主完整性等级不同时（应用管理员 High、拖放源 explorer 是 Medium），要对自己那几个窗口显式放行 UIPI 消息。
  - **为什么**：低完整性发给高完整性窗口的 `WM_DROPFILES` 在到达前被**静默丢弃**——能拖、光标可放，窗口却毫无反应、不报错、无日志；而自动化测试走 `WM_COPYDATA` 反而是"通过"的。
  - **怎么做**：`ChangeWindowMessageFilterEx(h, WM_DROPFILES/WM_COPYDATA/WM_COPYGLOBALDATA, MSGFLT_ALLOW, nullptr)`，只放行这几个窗口类消息，不是全局放宽权限。（历史：踩坑记录 第21.1节）
- **规矩**：跨进程改别的进程里 EDIT 的内容要发系统消息 `WM_SETTEXT`，不能用 `SetWindowText`。
  - **为什么**：`SetWindowText` 对别的进程的窗口只能改"窗口标题"、写不进别人内存——探针调用返回成功、读回也是新值，应用那边拿到的却还是旧值。
  - **怎么做**：`SendMessageW(edit, WM_SETTEXT, 0, 缓冲区地址)`（字符串由 user32 封送，缓冲区要自己保活）；注意跨进程 `WM_SETTEXT` 不产生 `EN_CHANGE`。（历史：踩坑记录 第25.2节）

## 三、跨 DLL / ABI

- **规矩**：跨 DLL 禁止 `delete`；模块必须导出 `nppdock_module_destroy`，主 DLL 调用它。
  - **为什么**：各 DLL 用 `/MT`，各有独立 CRT 堆，跨堆释放会崩。
  - **怎么做**：功能 DLL 不得链接主 DLL 的实现符号（工具函数写成 `inline` 放头文件），并保证模块能干净地反复加载/卸载（静态状态在卸载后失效）。（历史：踩坑记录 第5.1节）
- **规矩**：构建后用 `dumpbin /dependents NppDock.dll` 自检静态链接。
  - **为什么**：目标机缺 VC 运行库时插件会**静默不加载**，是最难查的一类失败。
  - **怎么做**：输出里出现 `MSVCP*/VCRUNTIME*/MSVCR*/api-ms-win-crt*` 任一即为没静态链接；期望结果只有系统 DLL（USER32/KERNEL32/COMCTL32/SHELL32/GDI32）。（历史：踩坑记录 第5.2节）
- **规矩**：`DockedWidgetData::pszModuleName` 填 `L"NppDock.dll"`。
  - **为什么**：它被宿主当作 `config.xml` 里 `<PluginDlg pluginName=...>` 的 key，填错或留空则面板停靠位置、可见性重启后无法恢复。
  - **怎么做**：填 DLL 文件名——不是面板标题，不是任意标识符。（历史：踩坑记录 第3.1节）
- **规矩**：别用 `0` 表示"未设置"——它和合法枚举值撞车。
  - **为什么**：`uMask` 高 4 位表示默认停在哪个容器，写 `0` 是"未指定"，而 Notepad++ 的兜底值 `CONT_LEFT` 本身也等于 0，于是"没填"与"填左边"无法区分，面板跑到左边；且 `config.xml` 里已有的 `curr="0"` 记录**优先于** `uMask` 默认值。
  - **怎么做**：显式填 `DWS_DF_CONT_BOTTOM`；改停靠位置前先删 `config.xml` 里该条记录。（历史：踩坑记录 第3.2节）
- **规矩**：面板可见性自己维护唯一状态源，不去问窗口；判断之前先别做动作。
  - **为什么**：SDK 根本没有"查询面板可见性"的消息；`IsWindowVisible` 不适合作判据（`hClient` 与宿主停靠栏 `WS_VISIBLE` 不同步）；宿主启动时会把已注册面板**一律显示**、不读自己写的 `isVisible="no"`；旧实现开头那句无条件 `NPPM_DMMSHOW` 正是"关掉后打不开"的根因。
  - **怎么做**：状态存 `panel.ini`，注册后按上次状态主动 `NPPM_DMMHIDE`；用户可能用面板 ✕ 关它而宿主不发通知，所以退出前要与真实可见性对账后再落盘。（历史：踩坑记录 第3.4、3.5、18.3节）

## 四、嵌入与 DPI

- **规矩**：应用在创建任何窗口之前，把本进程 DPI 感知等级设成和宿主一致。
  - **为什么**：跨进程 `SetParent` 时系统会对子窗口做一次 forced reset（MSDN `SetParent` 备注有专表，所有 Windows 版本都这样），两边坐标空间不一致 → 应用只铺满 2/3，右边和下边露白。
  - **怎么做**：优先 `GetWindowDpiAwarenessContext(hDockParent)` 抄宿主上下文，读不到再退回 per-monitor-v2（用 `GetProcAddress` 动态取，避免依赖新 SDK 类型和 manifest）。（历史：踩坑记录 第8.4节）
- **规矩**：用 `SystemParametersInfoForDpi(..., g_dpi)` 取字体度量，别自己再乘一次缩放。
  - **为什么**：`SPI_GETNONCLIENTMETRICS` 给的字号**本身已按 DPI 缩放过了**，再乘 `dpi/96` 会放大 1.5 倍——错了不报错，只有肉眼看出来（按钮字比系统 UI 大一半）。
  - **怎么做**：优先 `SystemParametersInfoForDpi` 直接取当前 DPI 的一份度量原样用；老系统没有它时才退回"按系统 DPI→当前 DPI 补正**一次**"。（历史：踩坑记录 第20.1节）
- **规矩**：`SetProcessDpiAwareness` 在 **shcore.dll**，不在 user32.dll。
  - **为什么**：在 user32 里 `GetProcAddress("SetProcessDpiAwareness")` 永远拿到 NULL → 兜底全失效 → 进程 unaware：窗口被整体拉伸、字发虚，跨进程鼠标坐标还会被虚拟化成 2/3（探针发 (120,37) 应用收到 (80,25)）。
  - **怎么做**：按优先级 `AdoptHostDpiAwareness`：①抄宿主上下文 ②`SetProcessDpiAwarenessContext(PMv2 == -4)` ③`LoadLibrary("shcore.dll")` 再取 ④`SetProcessDPIAware()`；一处实现，别让每个应用各写一份。（历史：踩坑记录 第21.4节）
- **规矩**：`IsWindowVisible` 会查整条父链——父窗口不可见，子窗口一律返回 FALSE。
  - **为什么**：宿主窗口没带 `WS_VISIBLE` 也没 `ShowWindow` 时，应用明明嵌好（窗口树里已是子窗口、尺寸也对），插件却报"未在超时内挂载"并强杀进程；多页共存时非当前页整页被宿主藏起，控件被误判"不在"。
  - **怎么做**：挂载判定放宽为"宿主下出现了子窗口"、可见性只记录不作门槛；判控件"在不在"用控件自己的 `WS_VISIBLE`；宿主铺好尺寸后显式 `ShowWindow(hHost, SW_SHOW)`。（历史：踩坑记录 第8.3、6.3、20.3节）
- **规矩**：`wWinMain` 的 `lpCmdLine` **不含程序名**，喂给 `CommandLineToArgvW` 前要用 `GetCommandLineW()`。
  - **为什么**：`CommandLineToArgvW` 按"含 argv[0]"解析，第一个开关会被当成 argv[0] 吃掉——`--selftest` 静默什么都不输出、`--dock-parent` 永远匹配不上（不报错不崩，只是安静走错分支）；同类地，无条件 `AttachConsole(ATTACH_PARENT_PROCESS)` 会覆盖继承来的 stdout，重定向时输出全丢。
  - **怎么做**：用 `CommandLineToArgvW(GetCommandLineW(), &argc)`；`AttachConsole` 前先看 `GetFileType(GetStdHandle(STD_OUTPUT_HANDLE))`，只有 `FILE_TYPE_UNKNOWN` 才调；关键分支、命令行解析一律打日志。（历史：踩坑记录 第8.10、8.11节）

## 五、应用界面与交互

- **规矩**：ComboBox 的"高度"是**展开后**的总高，且 `CB_SETITEMHEIGHT` 必须在 `SetWindowPos` **之后**。
  - **为什么**：`cy` 不是闭合高度（闭合高度由系统按条目高度+内边距算），且任何几何变更都会把条目高度重置回字体默认值——顺序反了，下拉框闭合高度比旁边按钮矮 7px（32 vs 39），看着像 DPI 误差。
  - **怎么做**：`cy` 给 `rowH + Dp(4) + rowH × 条目数`，再设条目高度让闭合高度回到 `rowH`；`CB_SETITEMHEIGHT` 传 `-1` 设选择框、传 `0` 设列表项，两个都要设；`AlignComboItems()` 焊死在 `LayoutChildren()` 里紧跟 `SetWindowPos`。（历史：踩坑记录 第12.2、12.3节）
- **规矩**：路径框可编辑后，**UI 是唯一真相源**，别维护影子副本；程序化回填要加护栏。
  - **为什么**：用户改了框没按回车 → 点的"计算"算的是上一个文件；程序回填触发 `EN_CHANGE` → 误判成用户改了 → 把算好的结果清掉。
  - **怎么做**：读的时候从控件读（`ReadPathFromEdit()`）；回填用 `g_syncingPath` 包住程序化的 `SetWindowText`、期间忽略 `EN_CHANGE`；`EN_CHANGE` 只标"已过期"，别直接清空结果框。（历史：踩坑记录 第12.4节）
- **规矩**："同一个控件换身份"（删除↔撤销、下载↔取消）时，**画法、可用性、点击处理、窗口标题**四处都要跟着身份走。
  - **为什么**：漏一处就出"看着是取消、其实是灰的"这种只有交互才发现的 bug（忙碌时把变身的取消按钮自己也禁用了，点它毫无反应）；owner-draw 按钮不存文字，探针认不出按钮。
  - **怎么做**：忙碌时只让 `id == g_busyBtn` 那个保持可点；用 `SyncBtnCaptions()` 每次状态变都把名字写进窗口标题（探针/读屏能读）。按钮宽度表要同时含两个标签，否则变身那一刻文字被裁。（历史：踩坑记录 第25.1、26.6、16.5节）
- **规矩**：字体要回读确认，字号用比例、em 用 `lfHeight`。
  - **为什么**：`CreateFont` 找不到字型会**静默替换**成别的，不校验就以为设上了；字号取正文的 `tmHeight` 会偏大（`tmHeight` 含字体行距，中文行距远大于等宽字体）。
  - **怎么做**：字体依次试 `Consolas`→`Lucida Console`→`Courier New`，用 `GetTextFaceW` 回读；字号取正文的 `lfHeight`（em），"小一号"用比例（8/9）而不是减固定像素（基础字号在不同机器是 9/10/11pt）。（历史：踩坑记录 第19.6、20.2、16.4节）
- **规矩**：行内命中测试必须与绘制**共用同一份几何算法**。
  - **为什么**：若"画"和"点"各算一遍坐标，迟早错位——表现是"点垃圾桶却打开了文件"，且只在某些宽度下出现。
  - **怎么做**：一个 `RowLayout` 同时被 `DrawListRow` 与 `ListHitTest` 调用，坐标只此一处；只在图标热区吃掉 `WM_LBUTTONDOWN`，其余放给原生列表框。（历史：踩坑记录 第21.8节）
- **规矩**：`WM_CONTEXTMENU` 的 `lParam` **本来就是屏幕坐标**，别再 `ClientToScreen`。
  - **为什么**：坐标多转一次不会报错，只是菜单飞到屏幕角落（超出屏幕被系统裁到边上）；对比：`WM_RBUTTONUP` 给的是客户区坐标。
  - **怎么做**：直接用 `GET_X_LPARAM/GET_Y_LPARAM`，只在 `(-1,-1)` 时 `GetCursorPos` 兜底；修完把坐标打进日志。（历史：踩坑记录 第8.1节）
- **规矩**：`SysTabControl32` 在标签条空白区对 `WM_NCHITTEST` 返回 `HTTRANSPARENT`，要子类化自己回 `HTCLIENT`。
  - **为什么**：空白区右击"什么都不会发生"，所有常规探路工具（`WindowFromPoint`/`ChildWindowFromPointEx`）都显示"点在标签条上"，真实右键却被 Windows 转给了父窗口；控件的 `NM_RCLICK` 也分不清点在标签项还是空白处。
  - **怎么做**：子类化标签条，落点在窗口矩形内就回 `HTCLIENT`；右击用 `TabCtrl_HitTest` 分辨标签项/空白（判据是"命中了已存在的页"，不是 `item>=0`），并 `return 0` 吃掉（否则菜单弹两遍）。（历史：踩坑记录 第8.12节）
- **规矩**：拖动排序时目标槽位必须**冻结**。
  - **为什么**：标签项宽度取决于标题文字，每帧用 `TCM_HITTEST` 现算会"搬完宽度变了、命中又变回去"，一个拖动来回抖 6 次最后回原位。
  - **怎么做**：`WM_LBUTTONDOWN` 时把标签项矩形冻结一份，拖动只用这份算；设 4px 位移阈值（否则"点一下切页"被当成拖动）；拖动不改变选中页，选中跟着页对象走。（历史：踩坑记录 第18.1节）

## 六、配置文件与状态落盘

- **规矩**："值域只差 1"的解析 bug 要用**往返测试**才能钉住。
  - **为什么**：`line.find('1', 9)` 越过了 `"visible=1"` 的行尾（只有 9 字节、下标 0–8），`find` 永远返回 `npos`——文件内容对、日志对，重启后面板却永远恢复成隐藏，单测看文件内容查不出来。
  - **怎么做**：`find('1', 8)`（`"visible="` 长 8）；回归护栏做往返测试——写状态→重新注册→断言行为（`visible=0` 重启必发 HIDE，`visible=1` 必不发）。（历史：踩坑记录 第2.4节）
- **规矩**：加了"事件回调自动保存"后，要问"还有谁会在我之后触发这个回调"——生命周期末尾的析构会把好状态抹成空表。
  - **为什么**：容器 `destroy()` 走 `closeAllPages()`，那一刻页面已空、回调又存一次盘 → 正常关闭后 `panel.ini` 里 `page0=` 不见了（强杀反而正常）。
  - **怎么做**：加全局闸门 `g_stateFrozen`，`NPPN_SHUTDOWN` 里存完立刻拉下来；判断方法：把回调的所有调用点列出，逐个问"这一刻数据是真的还是已清空"。（历史：踩坑记录 第10.1节）
- **规矩**：恢复过程中一律冻结落盘，恢复完再主动补存一次。
  - **为什么**：恢复 N 页 = 触发 N 次回调 = 写 N 次盘，每次写的都是"恢复了一半"的列表，中途失败/崩溃就固化残缺；懒加载"待恢复"期间内存页列表是空的，一次普通保存就把用户上次开着的页抹掉。
  - **怎么做**：恢复前 `g_stateFrozen=true`、完再放开并补存（写真实结果）；待恢复期间只写 `visible=`，把文件里原来的 `pageN=`/`current=` 原样抄回来。（历史：踩坑记录 第10.2、18.4节）
- **规矩**：跨会话存"引用"存稳定的身份标识，别存易变的序号。
  - **为什么**：记下标 `page0=0` 时，增删一个 exe 后下标整体漂移 → 重开时打开的是**另一个应用**；记文件名则找不到就跳过、不误伤。
  - **怎么做**：`page0=`/`current=` 都记文件名（一个应用只允许开一页，文件名↔页下标双向唯一）。（历史：踩坑记录 第10.3节）
- **规矩**：程序对"人也在改"的配置文件只能**读-改-写**，绝不拿内存整份覆盖。
  - **为什么**：`OpenConfigForUser()` 第一句 `Save(g_cfg)`、以及 `WM_CLOSE`/`WM_DESTROY`/定时器的整份回写，会把用户手改的内容冲掉（表现："改完保存，重开改动没了"）。
  - **怎么做**：去掉"打开配置就整份 Save"；唯一改配置动作走"先读磁盘、只覆盖那几项、再整份写回"；把重读配置放在 `Connect()` 开头做到"改完点刷新即生效"；更彻底的办法是**把界面上的配置入口删掉**，少一个写者就少一整类并发问题。（历史：踩坑记录 第22.1、19.2、24.1节）

## 七、远端命令与 shell

- **规矩**：`ssh` 的"认证失败"和"远端命令被拒"长得很像，要用左括号区分。
  - **为什么**：认证失败是 `Permission denied (publickey,password).`（**带左括号**），远端命令失败是 `Permission denied`（**不带**）；只匹配裸串会把"远端目录没权限"误报成"用户名或密码不对"，把排查方向整个带偏。
  - **怎么做**：按 `Permission denied (` 判认证；裸的归到"已登录但远端目录没写权限"，提示改 `remote_folder`。（历史：踩坑记录 第22.2节）
- **规矩**：判"是不是应用的锅"时，别把"ssh **尝试**某动作"当成"该动作**成功**"，要拿到**结果**（退出码 0 + 命令输出回来）。
  - **为什么**：`ssh -vvv` 的 `spawning … as subprocess` 只说明 ssh 尝试去拉 askpass，不说明它真读到了密码；当初据此下"密码被服务器拒绝"的结论是错的（账密从头到尾都没错）。
  - **怎么做**：要判定就用"原样跑一遍并打命令/退出码/stdout/stderr"的 `--sshraw`；用 `od -c` 确认 askpass 吐出的就是密码本身（无多余换行/空白）。（历史：踩坑记录 第22.5、23.2节）
- **规矩**：应用认"我是 askpass"只能靠**环境变量**——ssh 拉起它时只把提示串当 argv[1]，不给任何开关。
  - **为什么**：旧代码靠 argv 里有 `--askpass` 认，永远匹配不上 → ssh 拉起的实例跑去建主窗口进消息循环，一次刷新弹 3 个关不完的窗口，且密码根本没发出去（服务器回 `Permission denied`）。
  - **怎么做**：用专用环境变量（`NPPDOCK_ASKPASS_MODE=1`），`wWinMain` **在创建任何窗口之前**先看它；判据取**或**（MODE / `SSH_ASKPASS` 指向本 exe），共同前提是"拿到了密码变量"，宁松勿紧。（历史：踩坑记录 第23.1节）
- **规矩**：远端原子写要连同**字节数**一起校验，失败分支末尾的 `false` 不能省。
  - **为什么**：连接被"正常关闭"而内容只到一半时，`cat` 会成功退出、`mv` 照样把残缺文件盖上去；少了 `false`，整条命令退出码会变成 `rm` 的 0，上层把"失败"当"成功了"。
  - **怎么做**：`{ cat > TMP && [ "$(wc -c < TMP | tr -d ' ')" = "N" ] && mv -f -- TMP DST; } && echo OK || { echo INCOMPLETE >&2; rm -f TMP; false; }`；命令里串 `&&`/`||` 时永远想一遍"最后一步的退出码"。（历史：踩坑记录 第29.4节）
- **规矩**：任何"自己造的文件名 + 通配符清理"都要想一遍开头的点。
  - **为什么**：shell 的 `*` 和 `FindFirstFile` 都不匹配开头的点，`rm -f dir/.nppbackpack-tmp-*` 与临时名 `<原名>.nppbackpack-tmp-<pid>` 两条都对不上、残留清不掉。
  - **怎么做**：临时名改成"原名+后缀"（不再自己加点），清理时扫两个通配符（`*.nppbackpack-tmp-*` 和 `.?*nppbackpack-tmp-*`）。（历史：踩坑记录 第29.3节）
- **规矩**：宽字符转窄字符必须**显式选一种编码**，不能依赖 `std::string(w.begin(), w.end())`。
  - **为什么**：那是逐字符硬截成 `char`，ASCII 下永远正确、一遇中文就错且不报错——`便笺.txt` 发到服务器变成 `\xBF:.txt` 乱码文件名。
  - **怎么做**：一律走 `W2U8()` 转 UTF-8 再交给 `ssh`。（历史：踩坑记录 第23.3节）

## 八、探针与验证手段

- **规矩**：探针的 DPI 对齐要放在**模块 import 时**执行（且幂等），固定用 per-monitor-v2（物理像素）。
  - **为什么**：只在 `main()` 对齐不够——临时脚本 `import dock_app_probe` 直接用会跑在 DPI-unaware 空间，坐标差 1.5 倍、点击全飞；想"抄宿主声明的感知等级"更糟，本机 N++ 声明 system-aware 却按物理像素工作。
  - **怎么做**：启动打印 `[env] DPI 感知=…；屏幕=…`（含宿主声明值）；判据：任何"点击/坐标"类测试突然大面积失败，先量一遍换算比例。（历史：踩坑记录 第17.7、8.2节）
- **规矩**："抓屏+算指标"的判据要先证明"这一帧是我们的"，并且要有第三种"判不了"的状态。
  - **为什么**：抓的是屏幕像素，被别的窗口压住就抓到**别人的画面**——实测暗像素 75.92%（比"完整界面"高 20 倍，右下是别人在放视频）照样判 OK；把"样本无效"塞进"通过/失败"里，归到"通过"就是骗自己。
  - **怎么做**：抬到最前 + 容器上取 4 个采样点逐点 `WindowFromPoint` 校验命中是宿主后代，任一点不是就判 `skip`；三态用 ok/blank/skip，退出码 3 表示"这次没测"（锁屏时注入全被安全桌面收走，也应 SKIP 而非 FAIL）。（历史：踩坑记录 第15.1、15.2、20.4节）
- **规矩**：用"抓屏+数颜色"量跨进程 UI 时，必须先让消息循环走完一轮。
  - **为什么**：拖动回调里 `SetCursorPos` 后立刻截图，而补重画走 `PostMessage` 还没派发 → 量到的是探针自己造成的"假空白"，差点得出"拖动中确实会白"的错误结论。
  - **怎么做**：截图前先 `time.sleep(0.30)` 让消息队列排空（真人两次鼠标移动间隔约 8ms，补重画早跑完了）。（历史：踩坑记录 第9.4节）
- **规矩**：验证"用户能不能点出来"时，别用设置状态的 API 代替点击——探针要复现用户那条路径。
  - **为什么**：探针 `set_sel()` 直接发 `LB_SETSEL`，根本不过 `WM_LBUTTONDOWN`，所以"点文件选不中"它测不出来（用户点一下没感觉、再点一下反而取消选中）。
  - **怎么做**：发真的 `WM_LBUTTONDOWN`（带坐标）再读 `LB_GETSELCOUNT`。（历史：踩坑记录 第27.2节）
- **规矩**：断言要和"本次操作造成的改变"对齐，别和"世界的某个绝对状态"对齐。
  - **为什么**：断言"关页面后 md5 进程数为 0"，但 dock 里本来就嵌着一个实例 → 永远报"残留 1 个"。
  - **怎么做**：记操作**前**的进程数，比较 `after - before`。（历史：踩坑记录 第13.2节）
- **规矩**：等某个"会出现的东西"时别 `sleep(固定秒)`，要轮询条件；看不见的过程要留**可数**的痕迹。
  - **为什么**：固定睡眠必然出现"一次过一次不过"；"刷了两次"肉眼甚至探针都数不清，只能靠"我记得只刷了一次"辩护。
  - **怎么做**：记基线行数→循环读到出现目标行；在"真的重拉了一次"处埋一行轨迹日志（`刷新文件栏：N 项`），之后 `grep -c` 就是答案；模态菜单外部看不见，构建时也把菜单项写进日志。（历史：踩坑记录 第27.8、27.6、28.2节）
- **规矩**：拖分隔条前先 `WindowFromPoint` **验证落点**。
  - **为什么**：`nsdockspliter` 只有 4px 高，抓偏几像素就落到面板标题栏上——那不是 resize 是移动，一次 `--dy -140` 把整个面板拖出 N++ 窗口且不自愈。
  - **怎么做**：落点类名不含 "spliter" 就中止；同名控件多个时挑"有尺寸的那个"（第一个可能是退化 0×0）；截图前判容器高 > 0。（历史：踩坑记录 第13.3、13.4节）
- **规矩**：跨进程点菜单前要**校验菜单内容**，不是只看"有没有菜单弹出"。
  - **为什么**：右击没命中标签项时弹的是「添加应用」，点它的第一项会让页数**越关越多**（这是"跨进程传指针写崩 N++"的孪生兄弟：跨进程点错菜单照样把界面搅乱）。
  - **怎么做**：只点含「关闭」的那项，没有就 `press_esc()` 退出；落点从近到远退让；`close_tab_at` 要校验"条目矩形在菜单窗口内 + 页数真的降了"（关页异步，单次读数滞后一拍，要等读数稳定）。（历史：踩坑记录 第17.3节）
- **规矩**：被测程序会弹自己的窗口时别用全局合成输入；探针驱动"会弹模态窗的行为"一律用 `Post`。
  - **为什么**：合成鼠标会打到弹出来的资源管理器窗口上（"下载能过、双击进目录挂了"，非常像应用的 bug）；同步 `SendMessage` 要等窗口过程返回，而它要等模态循环/整轮测试结束 → 互锁卡死；非前台进程里 `SetForegroundWindow` 会被系统静默拒绝，点击落到别处（读到上一次的剪贴板）。
  - **怎么做**：改消息驱动（`LB_SETCURSEL`+`WM_COMMAND(LBN_SELCHANGE)`、直接 `WM_LBUTTONDBLCLK`）；用 `PostMessage` 驱动；先把窗口用"两步法"抬起来（`TOPMOST→NOTOPMOST→SetForegroundWindow`）。（历史：踩坑记录 第24.2、25.3、17.2、13.1节）

## 九、工程习惯

- **规矩**：注释**绝不**以反斜杠结尾。
  - **为什么**：C/C++ 行尾反斜杠是续行符，会把下一行吞进注释——症状是"结构体少了一个成员"，报错却是"不是该结构体的成员"，最隐蔽。
  - **怎么做**：`NppDockApi.h` 里有专门标注，写"含结尾反斜杠"的路径注释时特别注意。（历史：踩坑记录 第2.1节）
- **规矩**：日志**绝不写死期望值**，必须打真实字段。
  - **为什么**：原来日志写死 `"槽位 CONT_BOTTOM"` 字面串、根本不读 `tb.uMask`，等于自己关掉了报警。
  - **怎么做**：用 `swprintf_s` 打真实值；关键分支（尤其"程序什么都没发生"的命令行解析）一定要打日志——它不报错不崩，只是安静走错分支。（历史：踩坑记录 第3.2.2、8.10节）
- **规矩**：脚本里定位目录用"向上找特征文件"，不许出现连续两个以上的 `..`；一个项目里也不该有多个都叫 "root" 的东西。
  - **为什么**：目录层级一动，数 `..` 的地方**全部静默指错**——不报错不崩，只是"找不到文件"，错误信息长得像磁盘/权限问题、白绕一圈；插件私有数据 `_t/` 挂插件目录、宿主的根是另一个东西，混用时会写到不存在的目录。
  - **怎么做**：定位工作区根找 `sdk/PluginInterface.h`，定位宿主根找 `notepad++.exe`；加语义明确的 `plugin_dir()` 并在 docstring 写清与 `repo_root()` 的区别。（历史：踩坑记录 第14节）
- **规矩**：用脚本写文件必须先验证语法、写临时文件、再原子替换。
  - **为什么**：`open(path,"w")` **参数校验失败也会先清空文件**——`newline="\n"` 手滑写成双反斜杠，Python 抛 `ValueError`，但异常是在 5173 行的文件被截断成 0 字节**之后**才抛的。
  - **怎么做**：`s = io.open(p,encoding="utf-8").read()` → 改 → `ast.parse(s)` → 写 `p+".new"` → `os.replace(p+".new", p)`；动手前先 `shutil.copy2(p, p+".bak-<版本>")` 留一份自己的备份。（历史：踩坑记录 第27.4节）
- **规矩**：按标记/区间替换代码时，锚点要带足够上下文，且先断言唯一再写盘。
  - **为什么**：`index()` 命中的可能是文件开头的**前向声明**而非定义——轻则把中间的函数一起删掉（`NameError`），重则让整段被复制成两份（2500 行变 4575 行，编译器报"重复定义"）。
  - **怎么做**：锚点带上左花括号（前向声明没有 `{`）或从已知位置往后找；写盘前先断言 `content.count(anchor) == 1` 并数一遍关键符号出现次数；按跨度替换前先 `grep -n '^def '` 核对区间内所有函数名。（历史：踩坑记录 第26.1、20.6、19.5节）
- **规矩**：运行期要填的表/对象不能声明成 `const`，绝不用 `const_cast` 绕。
  - **为什么**：带常量初始化的静态 `const` 对象会被链接器放进只读段（`.rdata`），一写就是 `0xC0000005`；因跑在 `WM_CREATE` 里，表现成"窗口起不来 + WER 事件 `c000041d`"，而 `c000041d` 只告诉你"崩在某个回调"。
  - **怎么做**：运行期要填的表声明成非 const；加 12 行 `TraceLog` + `SetUnhandledExceptionFilter` 比 WER 好定位（关键判据：`c000041d` + "窗口起不来" ≈ 先怀疑窗口过程/`WM_CREATE`）。（历史：踩坑记录 第17.1节）
- **规矩**：重写整个文件时优先搬旧版里"有血泪注释的段落"；删源码要记得删 DLL；动老函数前先读它的注释。
  - **为什么**：那些注释之所以在就是因为踩过——重写 `nettest.cpp` 时把正确的字体代码换成"再乘一次缩放"，字体被放大 1.5 倍；容器靠扫 `NppDock_*.dll` 发现功能页，删了源码但旧 DLL 还在目录里它照样被加载；老函数注释里往往写着"为什么是这样"，"顺手加个功能"正是踩碎理由的最常见方式。
  - **怎么做**：重写前翻一次旧实现（备份文件里往往留着正确版）；部署步骤主动清理 `NppDock_*.dll` 历史遗留；改老函数先读注释。（历史：踩坑记录 第20.1、4.4、29.9节）
